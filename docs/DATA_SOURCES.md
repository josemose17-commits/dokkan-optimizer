## Gate for a future real-data adapter

1. Record the exact source, policy URL/version, permitted access method, license/permission, attribution requirements, and which fields/assets are covered. Resolve automated access, caching, and redistribution before downloading.
2. Prefer a permitted versioned export or documented API. Preserve source IDs alongside internal IDs, region/language, awakening/version state, source revision/hash, retrieval time, and verification date. Never overwrite synthetic fixtures with real records.
3. Validate a small sample against authoritative in-game descriptions or official notices. Store evidence per mechanic; label incomplete/unsupported mechanics. A text description is not automatically an executable formula.
4. Pin an initial snapshot. Apply reviewed diffs after game updates, track deletions/revisions, recheck terms, and reverify affected mechanics. Use the source's permitted rate/cadence; no background scraper ships in this prototype.
5. Add independently worked mechanics examples before introducing a real evaluator. Keep verified data out of the synthetic scoring engine, which deliberately rejects it.

Remaining blocker: an authorized, maintainable data acquisition path **plus** a verified mechanics model. Resolving only the license or only the parser is insufficient for real recommendations.
